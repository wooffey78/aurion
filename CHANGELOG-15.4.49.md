# CHANGELOG 15.4.49

## Objet de la livraison

Intégration des exigences fonctionnelles des **prompts 01 à 09** (fiches `cahier-des-charges/01…09`,
reprises à l'identique par l'éditeur) dans la version 15.4.48, selon la méthode du dépôt :
audit factuel préalable (quatre audits indépendants couvrant les neuf prompts), blocs atomiques
additifs (migrations **103 → 109**), **aucun retrait de fonctionnalité**, aucune migration
existante modifiée, tests avant/après et traçabilité complète.

**Résultat de la vérification** : `tsc --noEmit` + build 0 erreur ; suite complète `node --test`
**706 tests — 628 pass, 0 fail, 78 skipped** (les sauts sont les tests d'intégration PostgreSQL,
non exécutables sans base provisionnée — comportement inchangé ; la recette 15.4.49 est
livrée dans `tests/v49-blocks-01-09.integration.test.mjs` pour rejouage sur base réelle).

## Règles respectées

- Aucune migration existante modifiée (103 → 109 additives et idempotentes) ; aucun push ni déploiement.
- **Aucune fonctionnalité retirée** : l'édition d'une facture envoyée non réglée est conservée (step14) ;
  la suppression d'un client sans document envoyé est inchangée ; le moteur de propositions, le
  catalogue, le stock, les achats, la comptabilité et l'agenda fonctionnent à l'identique.
- Les actions sensibles restent des validations humaines : dérogation d'agenda = `allowConflict` + motif
  audité ; fusion de clients = `confirm` + motif audité ; rejeu d'événement = motif, owner/admin ;
  expiration des devis = bornée aux documents créés à partir du 21/11/2026.

## Limites honnêtes (non livrées dans cette version)

- **Ordre de travail central (prompt 08)** : l'objet « intervention au sens ordre de travail »
  (statuts planifiée/en cours/terminée, checklist, prévisionnel vs réel à la clôture, affectation)
  reste un chantier dédié — cette livraison apporte les libérations de réservations exigées et
  s'appuie sur les réservations 095 existantes ; `releaseQuoteReservations` n'est plus un code mort.
- **Portail client** : inchangé (fondation 14 de la 15.4.48) ; les décisions de devis restent côté entrepreneur.
- **Fusion multi-téléphones/e-mails/contacts** (prompt 06) : les coordonnées multiples structurées
  (contacts, consentements) ne sont pas livrées ; les instantanés, l'archivage et la fusion auditée le sont.
- **Récurrence/fuseaux exécutables** : les métadonnées (`recurrence_rule`, `timezone`) sont collectées et
  stockées ; l'expansion des récurrences à la lecture reste à venir (aucun faux événement déroulé).
- **Source de routage réelle** pour les déplacements : aucune intégrée ; le endpoint reste honnête (« inconnue »).
- **Canaux outbox** : le seul canal livré est le journal de bord in-app ; e-mail/push suivront le même contrat.
- Les batteries d'intégration PostgreSQL (dont la recette 15.4.49) restent à rejouer sur une base
  provisionnée — procédure inchangée (`AURION_INTEGRATION_TESTS=1` + `DATABASE_URL` + `AURION_ADMIN_DATABASE_URL`).
